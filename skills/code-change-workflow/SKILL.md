# 可回滚的代码改动工作流

这套流程把 DSH 的三个能力串成一条闭环：**检索 → 编辑 → 诊断 → 回滚**。
它存在的理由很直接：没有检索就会改错地方，没有诊断就会交付坏代码，
没有回滚就只能靠人肉记 diff。

> **顺序不可跳。** 跳过第 1 步会改错位置，跳过第 3 步会交付错误代码。

---

## 第 0 步：确认起点（5 秒）

改动前先问自己两个问题：

1. **这次改动是否可能整体撤回？** —— 如果可能，先记下当前 turn 号（`rewind_turn` 无参数时列出的数字）。
2. **目标文件我熟吗？** —— 不熟就不要靠 `grep` 猜，走第 1 步。

> 回滚点按 turn 自动记录，不需要你手动存档。你只需要在**要撤的时候**知道撤到哪一轮。

---

## 第 1 步：用 `codebase_search` 定位，不要用 `grep` 开场

`grep` 只在**你已经知道字面量**时用。当你知道"要做什么"但不知道"叫什么"时，用 `codebase_search`：

```
codebase_search({ query: "parse order book snapshot" })
→ src/adapter/exchange.rs:301  get_order_book_snapshot
```

**判定规则：**

| 情况 | 用什么 |
|---|---|
| 知道确切的函数名 / 错误信息 / 常量 | `grep` |
| 知道行为，不知道命名 | `codebase_search` |
| 要找某个符号的所有引用 | `Codebase 索引` + `grep` 交叉验证 |

拿到 `file:line` 后**必须**用 `read` 打开实际代码再动手。索引给的片段是截断的，
不足以支撑修改决策。

---

## 第 2 步：最小编辑

- 一次只改一个"意图单元"。修 bug 就只修 bug，不要顺手重构。
- 用 `edit` 而不是 `write` 覆盖整文件——覆盖会丢掉你没读到的内容。
- 改多个文件时，**按依赖顺序**改：先改被依赖的，再改依赖方。

---

## 第 3 步：读诊断，不要跳过

`edit` / `write` 成功后，工具结果里会自动附带：

```

<lsp-diagnostics file="src/adapter/exchange.rs">
42:7 error [typescript]: Type 'string' is not assignable to type 'number'.
</lsp-diagnostics>
```

**这条链路的含义：语言服务器已经检查过了。** 你需要做的是：

- **有 `error`** → 修掉再继续。不要留着"稍后再说"。
- **只有 `warning`** → 判断是否与本次改动相关；相关就修。
- **完全没有诊断块** → 说明该文件类型没有配置语言服务器，或者文件是干净的。
  前者意味着**你失去了验证**，此时应手动跑该语言的检查命令。

**显式复检**（改动较大、或想确认全局影响时）：

```
lsp_diagnostics({ file_path: "src/adapter/exchange.rs" })
```

---

## 第 4 步：需要撤回时用 `rewind_turn`

```
rewind_turn()                          # 列出有快照的 turn
rewind_turn({ turn: 3, dry_run: true }) # 先预览
rewind_turn({ turn: 3 })                # 执行
```

**关键性质：**

- 只还原**那一轮 turn 改动过的文件**，不会碰工作区里其它无关的未提交改动。
- 该轮**新建的文件会被删除**，不是清空内容。
- 快照是落盘的，Host 重启后仍可回滚。

**不要**用 `git checkout` / `git reset --hard` 做同类操作——那会连带丢掉别人的改动。

---

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用 `grep` 猜函数名 | 改到同名但无关的代码 | 先 `codebase_search` 确认语义 |
| 跳过诊断块 | 交付编译不过的代码 | 任何 `error` 必须当场修 |
| 一次改 10 个文件再验证 | 出错时不知道哪步引入的 | 改完一个可编译单元就验一次 |
| 用 `git checkout .` 撤回 | 丢掉无关改动 | 用 `rewind_turn({turn})` |
| 索引结果直接用 | 片段是截断的，误判上下文 | 必须 `read` 原文 |

---

## 何时不需要这套流程

- 单文件、单行、语义明确的改动（如改常量、改注释）。
- 纯文档 / 配置改动。
- 你已经在同一个文件上连续修改且诊断一直干净。

除此之外，按完整流程走。
