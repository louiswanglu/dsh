# 模型分工与缓存策略

核心事实：**你的缓存命中率已经有 97.7%**（334 亿 token 实测）。
所以本 skill 的目标不是"提高命中率"，而是**别把它搞坏**，同时让强模型只做它该做的事。

## 一、可用模型（provider: `anexto`）

| 模型 id | 上下文 | 输出上限 | 适合 | 不适合 |
|---|---|---|---|---|
| `deepseek-v4.1-flash` | 1M | 384k | 日常编码、搜索、批量改动 | 架构决策、深度审查 |
| `deepseek-v4-flash-0731` | 1M | 65k | 同上，输出更短 | 需要长输出的场合 |
| `claude-opus-5-5` | 1M | 128k | 审查、调试、架构、摘要 | 大批量机械劳动（贵） |
| `gpt-6.1-sol` | 1.05M | 128k | 交叉验证第二意见 | — |

## 二、主模型怎么选

**一个会话固定一个模型，中途不要切。** 切模型会让缓存 100% 失效，
之后的每一步都要重新预热，成本骤增。

| 场景 | 主模型 |
|---|---|
| 日常功能开发、改 bug、跑测试 | `deepseek-v4.1-flash` |
| 交易/资金相关代码审查 | `claude-opus-5-5` |
| 疑难调试、根因分析 | `claude-opus-5-5` |
| 大规模重构、架构设计 | `claude-opus-5-5` |

## 三、把重活派给 subagent，而不是切主模型

这是**省钱又能用上强模型**的唯一正确姿势：

```
主会话（flash，缓存稳定）
  └─ 派 subagent（opus）做一次审查 → 只把结论带回主会话
```

主会话的上下文和缓存不受影响，强模型只在子会话里消耗一次。

### subagent 参数

```
subagent({
  description: "审查交易逻辑",
  prompt: "……完整自包含的任务描述……",
  provider: "anexto",
  model: "claude-opus-5-5",
  agent_preset: "trading-reviewer"   // 可选，需在允许列表内
})
```

**注意**：`provider` 和 `model` 必须**同时**给，或都不给（继承父会话）。

| subagent 任务 | 建议模型 |
|---|---|
| 代码审查 / 安全审计 | `claude-opus-5-5` |
| 深度调试 / 根因分析 | `claude-opus-5-5` |
| 架构评审 | `claude-opus-5-5` |
| 批量文件搜索 / 机械重构 | `deepseek-v4.1-flash` |
| 跑测试、看日志 | `deepseek-v4.1-flash` |

## 四、会破坏缓存的行为（务必避免）

缓存命中的前提是**请求前缀完全一致**。以下操作会让前缀变化，缓存直接作废：

| 行为 | 后果 | 规避 |
|---|---|---|
| 中途切模型 | **整体失效** | 开会话前就定好 |
| 中途切 preset | 人格段变化，前缀废 | 同上 |
| 动态增删工具 | schema 变化，前缀废 | 别在会话中途加插件 |
| 压缩 | 一次性失效 | 无法避免，但要少触发（见下） |
| 频繁改 system prompt 内容 | 前缀废 | 规则写进 skill，而不是每轮现写 |

**特别提醒**：不要在会话中途加载/卸载插件。我们之前调试时反复重启验证，
那是开发行为；日常使用应该一次配好。

## 五、压缩与记忆

压缩是有损的，这一点无法回避。当前配置已优化为：

```yaml
retainRatio: 0.30              # 近期保留 30% 原文（默认 0.16）
summarizationModel: claude-opus-5-5   # 摘要用强模型写
```

**你的行为策略**：

1. **重要决策立刻落盘**，不要指望上下文记住。写进文件：
   - 架构决策 → `docs/decisions.md`
   - 踩过的坑 → 项目规则文件
2. 之后需要时用 `codebase_search` 或 `grep` 查回来。
3. 长任务做到**阶段性收口**：一段做完就总结一次，让摘要抓到重点。

> 记忆的真正保障不是"上下文不丢"，而是"关键信息在上下文之外有副本"。

## 六、开工检查清单

会话开始时问自己：

- [ ] 这个任务需要强模型吗？需要 → 一开始就选 opus
- [ ] 这个任务能拆成"主会话 + 若干 subagent"吗？
- [ ] 有没有该写进文件的决策，避免被压缩冲掉？

派 subagent 时问自己：

- [ ] 这个子任务值不值得用 opus？
- [ ] prompt 是否自包含？（子会话看不到主会话的上下文）
- [ ] 需要哪个 agent_preset？
